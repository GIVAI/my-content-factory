# Рабочая тетрадь (лид-магнит) → PDF

Генератор красивого PDF-воркбука с **настоящими полями для заполнения**:
человек скачивает файл, открывает в Acrobat Reader / «Просмотре» / браузере
и печатает ответы прямо в строчках. Или печатает на бумаге и пишет от руки —
макет рассчитан на оба сценария.

Стиль: **maroon + cream**, заголовки — Playfair Display, текст — Inter.

```
content/workbook.yaml   ← здесь живут все тексты. Правите только его
assets/styles.css       ← дизайн (цвета, отступы, типографика)
tools/render.py         ← YAML → HTML
tools/fetch_fonts.py    ← разовая загрузка шрифтов (уже выполнена)
build.py                ← сборка PDF
out/*.pdf               ← готовый файл
```

## Как собрать

```bash
pip install -r requirements.txt          # один раз
python3 build.py                         # собрать PDF
python3 build.py --preview               # + PNG-превью страниц в build/preview
python3 build.py --content content/другой.yaml --out out/другой.pdf
python3 build.py --no-fields             # версия только под печать, без полей формы
```

Нужен установленный Chromium (или Google Chrome) — он рисует макет.
Для `--preview` нужен `pdftoppm` (пакет `poppler-utils`).

## Как править содержание

Весь текст — в `content/workbook.yaml`. Раздел `meta` — название, автор,
подпись в колонтитуле. Раздел `pages` — список страниц.

Внутри текстов работает простая разметка: `**жирный**`, `*курсив*`,
`==выделение цветом==`.

### Типы страниц

| `type`    | что это                                                     |
|-----------|-------------------------------------------------------------|
| `cover`   | обложка: бордовый верх + кремовый низ, имя автора, «печать» |
| `divider` | шмуцтитул раздела: крупный номер, название, подводка         |
| `content` | обычная страница с блоками                                   |
| `outro`   | финальная страница с призывом и контактами                   |

### Типы блоков (внутри `blocks`)

| `type`      | назначение                                                     |
|-------------|----------------------------------------------------------------|
| `text`      | абзац                                                          |
| `lead`      | вводный абзац крупнее и светлее                                |
| `note`      | мелкая приписка серым                                          |
| `heading`   | подзаголовок внутри страницы                                   |
| `list`      | маркированный список                                           |
| `numbered`  | нумерованный список                                            |
| `quote`     | цитата (`text`, `author`)                                      |
| `callout`   | акцентная плашка (`title`, `text`)                             |
| `panel`     | карточка-контейнер для вложенных `blocks`                      |
| `spacer`    | пустое место (`size` в мм)                                     |
| **`field`** | вопрос + линейки для ответа (`lines`) — **заполняемое**        |
| **`box`**   | вопрос + рамка для свободного текста (`height` в мм, `grow`)   |
| **`checklist`** | чек-лист с настоящими галочками                            |
| **`grid`**  | таблица (`columns`, `rows`, `row_height`) — каждая ячейка поле |
| **`scale`** | шкала 1–10 кружками (`min_label`, `max_label`)                 |
| **`duo`**   | две колонки линеек «до / после» (`sides`)                      |
| `cols`      | две произвольные колонки блоков                                |

У полей (`field`, `box`, `grid`, `checklist`, `scale`) можно задать:
`label` — подпись капслоком, `q` — номер вопроса, `ask` — сам вопрос,
`hint` — курсивная подсказка.

У `box` есть `grow: true` — блок растянется на всё оставшееся место
на странице.

## Проверка вёрстки

При каждой сборке скрипт measure-проходом считает, помещается ли содержимое
в границы страниц, и предупреждает: `⚠ страница 5: содержимое не помещается`.
Тогда либо сокращаем текст, либо переносим часть блоков на новую страницу.

## Как это устроено внутри

1. `render.py` собирает HTML: каждая страница — блок ровно A4, поля для
   заполнения помечаются невидимой ссылкой `https://field.local/<имя>?t=<тип>`.
2. Chromium печатает HTML в `build/design.pdf`; ссылки превращаются
   в link-аннотации, из которых мы узнаём точные координаты каждого поля.
3. ReportLab строит прозрачный слой `build/fields.pdf` с настоящими
   полями формы (`/Tx` и `/Btn`) в этих координатах.
4. pypdf подкладывает дизайн под слой полей — получается готовый файл.

Шрифт полей ввода — стандартный Helvetica с флагом `NeedAppearances`:
просмотрщик сам подставляет начертание с кириллицей, когда человек печатает.
Это самый совместимый вариант — работает в Acrobat, «Просмотре» на macOS,
Chrome и Firefox.

## Шрифты

`assets/fonts/fonts.css` — Playfair Display и Inter (лицензия SIL OFL),
встроены в base64, поэтому сборка не зависит от интернета.
Обновить набор: `python3 tools/fetch_fonts.py`.
